# v0.11：每句话都有自己的表情

2026-10-15。继续 v0.10，不重写 AI、Renderer、TTS、SQLite 或行为状态机。
本轮落实用户的“根据回复判断每句话需要什么表情”，而不是扩展动作数量。

## 现在怎么体验

重新启动根目录 `01_启动完整角色桌面程序.bat` → 自由聊天。
在离线演示模式输入 **演示逐句表情**：

1. “诶？你想看看我说不同的话时，会有什么表情吗？” → 惊讶。
2. “这样一直看着我，我会有点不好意思的……” → 害羞。
3. “不过，能认真听我说话，我还是很开心。” → 开心。

点击“下一句”推进，文字尚未显示完时先补全文字。对话框也可点击；输入框之外的
空格/回车可推进。最后一句显示本轮结束状态；可以随时输入新消息，不必读完旧回复。
停止按钮取消剩余句子和等待中的文字/画面/声音，保持当前表情，不强制回普通脸。
现有三段预设分支剧情和游戏式设置/选择弹窗不变。

上述离线三句是作者预设标签，不是实际 AI 推理质量证明。
DeepSeek 接入后使用同一条分段播放路径；本轮没有真实云端调用。

## 新回复协议

```json
{
  "segments": [
    {"emotion":"surprised","action_tag":"idle","scene":"","intensity":0.6,"voice_style":"normal","speech":"诶？真的吗？"},
    {"emotion":"shy","action_tag":"idle","scene":"","intensity":0.7,"voice_style":"soft","speech":"你这样说，我会不好意思的……"},
    {"emotion":"happy","action_tag":"idle","scene":"","intensity":0.6,"voice_style":"normal","speech":"不过，我真的很开心。"}
  ]
}
```

- 1–6 段，每段一小句、一个情绪；多段每段最多 400 字，总长度含换行最多 900 字。
- 每段使用原有 `behavior.normalize_llm_reply` 白名单。未知动作降为 idle，未知情绪降为 neutral，
  未登记场景被清空；不会执行模型给的路径、命令、URL 或 PSB 编号。
- 接受旧的单对象 speech/reply 协议作为一段，**不会用本地关键词伪装成逐句 AI 情绪推断**。
- 流式预览只展示第一句，避免先把所有台词显示完再倒回第一句。完整 JSON 通过校验后才允许播放。
- 最终结果包含内存 `turn_id`、已校验的 segments、兼容聚合 speech 和首句计划。
  此时只解析/准备渲染计划，尚未触发动作，也不写聊天记录。
- 前端先加载当前句的表情图片，确认请求仍有效，再通过 `/api/chat_segment` 激活本句。
  原 `BehaviorRuntime` 按实际推进时机执行冷却、优先级、动作与场景锁；不提前排入后面的动作。

## 顺序、取消和历史记录

`ReplyTurn` 只保留一个活动回复，随机令牌有效 30 分钟，仅存在内存中。
必须按 0、1、2… 顺序激活；当前句请求重试返回同一份结果，不重复触发动作/写历史。
跳句、回放旧句、错误编号、过期、换角色/设置、被新回复替代均拒绝。

第 0 句激活时把用户输入和该句在一个 SQLite 事务保存；后续句只更新同一条 assistant 记录为
已经推进到的文本前缀。取消后未读尾句不会进入下一轮 LLM 上下文。
若图片未加载成功，不激活、不写入本句，用户可重试；网络中断等极窄窗口仍可能在激活成功、
界面完成展示之前留下当前句记录，但不会提前保存后面的句子。
清空历史也会作废活动回复；停止不会删除已展示记录，不会自动生成任何长期记忆。

接口增量：

- `POST /api/chat_stream`：最终返回分段结果；逐句白名单校验。
- `POST /api/chat_segment`：仅接受 `{turn_id,index}`，不得由前端重新提交任意台词/行为。
- `POST /api/chat_turn_cancel`：作废已完成生成但尚未读完的回复。
- 旧 `/api/chat` 开发接口保留整轮兼容模式；新聊天会作废旧逐句令牌。

前端 `ReplyPlayer` 独立管理准备、下一句、语音和取消代次。旧图片/旧音频完成回调不能恢复
已停止的回复；快速切换聊天、剧情、造型、保存设置时也会检查导航/请求是否仍有效。

## 语音边界

本轮仍以无语音体验为主。若开启已有 TTS，逐句只合成/播放当前句；点击下一句或发送新消息
会停止旧句声音。缺少语音模型时，提示失败但可以继续下一句，不把同一句重复播放作为重试。
当前不自动按音频结束推进下一句，不预合成所有语音；没有验证真实角色克隆声音。
Qwen 等 GPU 后台推理的强制取消、首包流式音频和模型驻留策略仍沿用 v0.10 的限制。
