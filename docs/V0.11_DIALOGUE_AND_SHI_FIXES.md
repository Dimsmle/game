# v0.11 本机修复：对话、口型与 shi 素材

2026-10-15。保留既有架构、用户的 AI 配置、正式聊天记录和角色选择。

## 本轮改动

- `studio/app.py`、`replies.py`、`behavior.py`：逐句模式不再同时要求顶层 speech；
  SQLite 的已读角色台词在发往模型时包装回 JSON segments 协议，避免第二轮上下文
  以纯文本示范错误格式。未读尾句仍不进历史。仅兼容完整 JSON 或完整 Markdown JSON
  代码围栏，不补括号、不从自然语言猜动作。格式失败只记录字符数、错误位置和是否为空。
- `studio/llm.py`：收到 finish_reason=stop 即结束，不再额外等待 DONE/EOF。
- `studio/web/game.js`、`app.js`：第一句网络预览平滑逐字显示，点击立即补全已收到文字，
  后续网络文字到达直接显示；其余句子点击推进，打字未完成则先补全当前句。
  网络尚未收到的内容无法提前显示。完整 JSON 校验后才激活行为和保存已读句。
- 无 TTS 时随文字显示周期切换当前表情的开/闭口 PNG；点击补全、停止、换句时闭口。
  实际音频播放时仍以音频音量优先。文字口型不是音素级唇形同步。
- 去掉“准备相应表情”遮挡提示；保留上一张脸等待新图，就绪后再切换对应台词。
- `emote_model.py`：当前关键帧 mask 的 0x400 位启用 opa 字段；opa=0 时不遍历
  该引用及子图层。原实现忽略此字段，闭眼仍绘制瞳孔，形成黑球。重新睁眼时当前
  mask 不再启用 opa，瞳孔恢复。不是永久隐藏瞳孔，也没有隐藏哭泣图层。
- `emote_model.py`、`behavior.py`、`main_desktop.py`：识别实际 Ａ／Ｂ／Ｃ 类表情预设，
  按当前模型存在的名称选择。17 个 shi 模型使用 Ｂ；之前被误分为动作。
  渲染缓存版本升至 5.4，旧表情和动作序列缓存/验收签名会失效，防止继续显示旧黑球。
- 测试显式指定 demo 或假接口，不再随用户修改默认 DeepSeek 设置而误调用真实服务。
