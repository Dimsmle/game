# v0.10：DeepSeek + 可切换本地语音的第一阶段

2026-10-15。在 v0.9 上增量实现，沿用行为映射、状态机、SQLite、场景与 Renderer，
没有重写架构。产品方向是双渲染后端的 AI 角色平台，但完整原生 E-mote 与 Live2D
仍不能因接口存在而被宣布实现。

## 已实现与使用

正常启动桌面程序 → 设置 → 自由聊天。舞台保留角色、回复、输入框和停止按钮，
不用进入开发工作台。设置 → 连接与角色设置可保存 AI/语音提供者。

- DeepSeek 官方模式默认 `https://api.deepseek.com`、`deepseek-flash`。该模式固定访问官方地址；
  需要其他地址时选 OpenAI 兼容模式。切换至官方模式会填入这两个默认值，不覆盖既有保存配置。
- 不具备密钥时保留离线演示，不能将演示回复当成实际 AI 的质量验收。
- 官方模式从启动进程环境读取 `DEEPSEEK_API_KEY`，自定义接口读取 `LLM_API_KEY`。
  没有密钥输入框，不写入设置、源码、Git 或日志。请在本机自行设置环境变量，**不要发送密钥给聊天**。
  设置环境变量后须关闭旧程序并重新启动，让新进程继承变量。
- 默认正常安装不包含 torch、Qwen、faster-whisper；本轮也没有安装或下载这些依赖及模型。

LLM SSE → `/api/chat_stream` NDJSON → 流式台词预览；完整 JSON 才产生本地校验后的行为。
模型首先输出 `speech` 字段，界面不显示 JSON/文件指令。最终 `emotion/action_tag/scene/intensity/voice_style`
均受本地白名单约束。兼容 `reply/emotion_intensity` 别名。未知 `look_away` 安全降为 idle，
不会借用无关 PSB。voice_style 当前只作为已校验元数据保留，**没有声称 Base 模型已支持语气控制**。

有 15 秒网络读超时、约 90 秒整轮时限、输出限制；仅在尚未收到内容时重试一次
临时网络或 429/5xx 错误，避免重复已显示文字。错误不展示上游错误正文或密钥。
停止按钮作废旧文字、旧图片、语音等待与播放；旧回复不执行动作。
完整且未取消的回复才将用户/角色消息在一个 SQLite 事务保存。角色或设置变化会拒绝旧结果。
上游无数据时后台取消最迟仍可能等待当前网络读超时；界面立即取消等待。

现有开发工作台的旧 `/api/chat` 接口保留兼容性；舞台新入口使用流式协议。
本轮实际自由聊天仍是**一轮一个情绪/动作决策**，多句逐句情绪轨道待真实 API 联调后扩展；
v0.9 预设剧情的逐句标签与选择分支保留。

## 隐私和记忆

云端对话会发送本轮文字、角色设定、近期 12 条消息；原有开关开启时会附加少量用户显式保存的记忆。
不自动上传图片、PSB、声音或 SQLite 文件。可关闭“允许已启用的长期记忆加入 LLM 请求”。
此开关不等于禁用近期对话上下文。游戏素材路径、纹理、编号不交给 LLM 选择。

## TTS 适配与仍需验证的内容

- `TTSProvider` / `TTSService`：Qwen3-TTS Base 本机可选适配、GPT-SoVITS API、浏览器系统本地语音。
- Qwen：首次真正合成才导入 GPU 依赖和加载模型，只接受显式本机 Base 目录、参考音频和参考文本。
  使用 CUDA BF16 + SDPA；合成结束或异常后释放本适配器的模型。每次非缓存合成都重新加载，
  这是优先保守释放的第一版策略，不是已经优化好的低延迟常驻服务。
- GPT-SoVITS 继续请求现有 `/tts`，不猜测或下载千岁权重。外部服务的模型卸载不受本程序控制；
  验证 Qwen 时须先自行关闭其他大型 TTS 服务，不能保证外部进程不会同时占显存。
- 系统语音只选择 WebView 中标记 `localService` 的语音，不是角色克隆；没有可用本地语音则提示并保留文字。
- 单个合成串行处理，前端语音播放队列可停止；停止也会取消尚未完成的音频下载、丢弃旧结果。
  **当前无法强杀正在运行的 Qwen GPU 推理或外部 GPT 请求**；它们可能继续到本次合成结束，再释放。
- WAV 验证与最多 32 个本机缓存，按文本、提供者和声音设置区分；修改参考文件时间戳会失效。
  大规模模型替换后的缓存版本管理、无缝模型热切换、真正音频分块首包播放尚待后续。
- Qwen Base 当前是完整 WAV 合成，不是流式音频；`first_audio_ms` 指完整音频首次可用时刻。
  记录冷加载、合成耗时、torch 峰值 allocated MB，以及释放后的整卡显存快照；它们不是同一指标。
- `/api/provider_status` 返回最近成功 LLM/TTS 指标及密钥“是否存在”的布尔值，无密钥值；
  本地 app.log 只记录性能数字与来源，不记录台词或参考文本。

## 准备 Qwen 的下一步（本轮未执行安装/权重下载）

已用 hf-cli 查询官方仓库，当前记录 revision：
`fd4b254389122332181a7c3db7f27e918eec64e3`。应完整下载 Base snapshot，不能漏掉 `speech_tokenizer/`。

之后经用户确认模型存放位置再执行：

```powershell
hf download Qwen/Qwen3-TTS-12Hz-1.7B-Base --revision fd4b254389122332181a7c3db7f27e918eec64e3 --local-dir "G:\开发游戏\Models\Qwen3-TTS-12Hz-1.7B-Base"
```

`requirements-tts-qwen.txt` 只记录可选依赖，不加入普通安装。
实际安装前按 PyTorch 官方 Windows/CUDA 选择器准备兼容版本，再安装可选 requirements，
避免随意覆盖现有桌面环境；尚未证明这一组依赖在本机真实推理可用。
本机当前为 RTX 4070 Ti SUPER（16376 MiB），查询时 used 2214 / free 13848 MiB，
**这不是 TTS 基准结果**，不承诺 6–10GB 占用或特定响应延迟。

参考素材准备好后，可显式运行离线基准（示例文件必须替换为实际授权文件）：

```powershell
.\.venv\Scripts\python.exe -m studio.tts_benchmark --model-dir "G:\开发游戏\Models\Qwen3-TTS-12Hz-1.7B-Base" --ref-audio "G:\Voice\reference.wav" --ref-text-file "G:\Voice\reference.txt" --out ".tmp\qwen_benchmark"
```

基准启用 Hugging Face 离线模式，不自动取权重；成功才输出 sample.wav 和 metrics.json。
克隆效果、首音频延迟、峰值显存、停止切换体验与至少 30 轮真实 DeepSeek 对话仍未验收。
