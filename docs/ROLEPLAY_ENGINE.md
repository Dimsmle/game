# Roleplay Engine — v0.14.1 本地集成

## 使用

正常从 main_desktop.py 启动，舞台右上角「✦ 角色设定」进入 `/roleplay/`。
这是同一个本机服务器和同一 SQLite，不是独立预览程序。

- 角色卡：编辑现有卡并保存，或新建后点击「设为当前角色」。仅保存新卡不会自动启用。
- 玩家人设：与角色资料独立；默认不绑定、不开启云端共享。显式启用且绑定后才会进入上下文。
- 六预设：自然日常、沉浸 Galgame、剧情小说、情感养成、开放世界、完全自定义。
  点击卡片应用；内置项不可覆盖，先复制再保存自定义预设。不是固定预设对话。
- 世界书：归属当前角色卡；关键词检索当前文本与最近六条已读历史，还受地点、好感、
  信任、关系、心情、flags、人工核实及隐私开关约束。未知地点不伪造触发。
  信任/关系/心情/flags 可在「其他条件 JSON」编辑，基础表单修改不会丢弃这些条件。
- 检查器：默认只有 ID、修订、命中/排除理由和预算，不展示完整聊天/Key。
  本地附加 Prompt 预览需确认，不调用云端；它不覆盖真实请求的 Trace。

换人设不会自动替换媒体模型、衣服、声音，也不会重新解释既有关系存档。
要隔离一段新关系及聊天，请先在舞台 HUD 新建/切换主存档，再设置它的角色卡绑定。
人物身份与媒体代码 kan/shi 没有未经审核的自动映射。

## 数据与迁移

沿用 `%LOCALAPPDATA%/CharacterLab/history.sqlite3`，不移动已有 GameStore/消息/记忆。
新表均为 rp_*；主库 user_version 仍由 game_db 管理。首次迁移前以 SQLite backup API
写入同目录 roleplay_backups；备份包含私人数据，不应上传。
DDL 与初始数据在同一个事务提交，失败回滚；Windows 连接显式关闭。

旧 role_name/persona 首次完整保存为 legacy_character 角色卡（介绍最多12000字），
不是玩家 Persona；后续启动/修改旧默认设置不会覆盖已编辑的卡。
旧设置留作备查，界面只读。当前名字和 AI 核心身份均来自启用的角色卡。
每个主存档拥有 card/persona/preset 绑定；卡和预设本身为可复用的资料库，编辑共享卡
会影响所有绑定该卡的存档。聊天、记忆和游戏状态继续按主 profile_id 隔离。

## 请求与权限

原有 stream_chat / 同步兼容路径保留 JSON 协议、行为标签、记忆隐私与已读历史，
调用同一个 bridge.extend_prompt → PromptComposer 加入角色、风格及条件世界知识。
预算是估算，不是模型官方 tokenizer：附加上下文默认上限4000、世界书1000；
状态、角色核心、风格优先，长介绍可能截断并在 Trace parts 标记。历史仍按原入口
限制最近12条；total_tokens_estimate 目前只估算 system 文本，不是完整请求总 token。
不静默删除本机完整人设，也不保证12000字每轮全部发送。

角色资料、世界书和预设是非可信叙事数据，不获得文件、SQL、CG、动作编号或 Key 权限。
行为仍经过 behavior/runtime/Renderer；AI scene 暂时清空。P1 模式禁用 RP 示例事件，
GameStore 是唯一养成数值权威；演示服务器自己的 rp_state 不是主游戏事实。
设定 epoch、profile generation 和 state revision 都进入 ReplyTurn 快照；
改卡/预设/世界书会取消当前生成并清掉未读尾句令牌，已读历史不会被抹去。
工作台选择带主存档快照，跨窗口切档后旧工作台需刷新，不能误给新存档换预设。

DeepSeek 凭据仍从 studio.credentials 读取（环境变量优先，其次私有 local_secrets.json）。
本次不注入 .env 读取器、不改密钥、不安装 STT/TTS/本地 LLM。

## 限制

尚无自动事件导演、CG、触摸、原生 E-mote 或 Live2D。预设 event_frequency 为预留参数，
不会自动提交事件。换预设不保证每条回复都有显著风格差异，更不保证模型不产生事实矛盾。
多窗口旧音频仍依赖前端停止/同步，并非服务端推送即时终止。没有角色卡删除或图形恢复功能。
人物设定和既有聊天可能保留过去身份信息，切换完全不同角色建议使用新主存档。
