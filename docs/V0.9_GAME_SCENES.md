# v0.9：先验证“回复与表情”，再扩展动作

按用户 2026-10-15 的新优先级，当前重点是每句话的情绪表现与成品游戏界面。
不要求部署 AI 或启用语音，也不继续把动作种类作为本轮主目标。

## 直接体验

双击根目录 `01_启动完整角色桌面程序.bat`。默认打开独立 WebView2 桌面窗口的游戏模式：
角色舞台、底部对话框、右上角设置按钮。没有资源仓库、图集、测试按钮或聊天调试面板。

首次选择一段对话，点击对话框、继续按钮或空格推进。文字尚未显示完时，第一次点击补全文字。
遇到回应节点会弹出选择框；选择以后，后续文本和表情沿对应分支继续。
每句话显示一个可关闭的情绪标签，方便检查表现是否合适。

本机明确选 kan_10：

```powershell
.\.venv\Scripts\python.exe main_desktop.py --model kan_10
```

开发工作台另用 `10_打开开发工作台.bat` 或 `--studio` 打开；游戏设置也有开发入口。
浏览器调试仍可使用 `--browser`，它和独立桌面窗口共享同一套游戏 UI。

## 三段预设文本

| 片段 | 表现重点 | 选择 |
| --- | --- | --- |
| 迟到的约定 | 不安 → 鼓脸 → 惊讶/温柔 → 害羞 → 开心 | 道歉或带来惊喜 |
| 今天有点累 | 认真倾听 → 悲伤/温柔 → 思考 → 安慰 | 倾诉或安静陪伴；傍晚转夜晚 |
| 藏起来的小惊喜 | 思考 → 不安 → 惊讶/害羞 → 开心 → 亲昵 | 送礼物或表达心意 |

当前是作者预设的台词与语义标签，**没有宣称 AI 已经自动判断了每句话**。
标签继续走既有 `studio.behavior`，选择当前模型真实存在的 PSB 面部预设，尊重已有人工表情映射。
未来 LLM 的逐句输出可复用此协议与播放器。动作本轮统一 idle，预设片段不会调用 LLM/TTS，
也不会写入用户聊天记录。用户看完本版后，可先调整台词、标签、脸部映射，再接实际 AI。

## 游戏界面与事件

- 设置中可重新选片段、切换场景、切换本机角色造型、隐藏情绪标签。
- 场景切换、回应和造型选择均使用模态选择框；背景未绑定时使用内置绘制的氛围场景。
- 剧情期间不会被自动昼夜或工作台定时事件抢占画面。
- 表情图先完成加载再展示对应台词；预热后续表情，避免文字和旧表情错配。
- 开始新片段或离开游戏模式会作废旧的异步加载，旧结果不会覆盖新场景。
- 语音保持关闭；文字逐字显示是视觉效果，不是音频或伪造口型。

## EXE 形态

`main_desktop.py` 默认进入 `?mode=game`，未来由现有 PyInstaller 脚本打包时也默认使用这个界面。
WebView2 作为嵌入式界面运行，不需要给使用者打开普通浏览器。所有新 CSS/JS 均在现有 web
资源目录，随构建脚本一起打包。本轮没有新建 Windows EXE，也没有运行或恢复 NativeSmoke.exe。
